--------------------------------------------------------------
1. WHAT WE ARE MAKING
--------------------------------------------------------------
A 2D pixel art game inspired by Dungeon Defenders: players
protect a crystal from waves of enemies using heroes and
placeable defenses. Stays pixel art (vector art was considered
and rejected). Effects may be smooth and glowy on top of the
pixel art, like the Terraria "Cooler Weapon Effects" mod:
the developer wants attacks to feel very smooth and juicy.

Rarities: common > uncommon > rare > epic > legendary > mythic
> artifact. Mythic = exceedingly rare, endgame. Artifact =
custom weapons with insane abilities, incredibly rare.
Higher rarity = cooler attack effects.

Weapon progression (agreed, like Dungeon Defenders 2):
- Upgrade level 0 to 15. Levels raise damage and attributes.
- At max level a weapon can upgrade its rarity ONCE (common
  wooden sword -> uncommon). Its level goes back to 0 and can be
  leveled to 15 again. Costs coins + crafting materials
  (not implemented yet).
- Attributes: random from a pool, values roll too (quality 0-1).
  Slots: common 1, uncommon 2, rare 3, epic 4, legendary+ 5 (max 5).
  Special attributes (life steal, blade waves, burn...) only on
  legendary+: legendary up to 1, mythic up to 2, artifact up to 2.
  Artifacts = custom fixed attributes + rollable ones.
  Rarity upgrade keeps all attributes and rolls the new slot.
- Attribute level 0-30 = upgrade level, +15 once the rarity was
  upgraded. Mythic/artifact (cannot upgrade) count as upgraded, so
  they start at 15. Combat level does NOT affect attributes.
  Some attributes step every few levels with a cap (blade waves:
  +1 every 5 levels, max 3).
- Combat level (separate from upgrade level): later islands drop
  higher combat level gear and have stronger enemies. Old weapons
  can have their combat level raised at the blacksmith.
- Hub area: blacksmith, shops, NPCs and other systems (not built).

The full vision belongs to the developer and is not written
down yet. Fill in details here as they get decided. Do not
invent design details that have not been agreed on.

2. HOW WE WORK
--------------------------------------------------------------
- The developer writes most of the game code themselves.
- Claude helps build the complicated and time-consuming systems.
- Every system Claude builds must be:
    * easy to understand
    * easy to expand for new content
    * usable by the developer without Claude's help

  (branch main). The push also updates the web build.


--------------------------------------------------------------
3. RULES
--------------------------------------------------------------
[Godot-first, not code-first]
Do not do things from code when it is not necessary. Use the
Godot node / scene / resource / inspector system instead:
- Build structure as nodes and scenes in the editor, not by
  creating nodes in code.
- Store data and configuration in Resources (.tres) and
  @export variables, not hardcoded values.
- Connect signals in the editor where it makes sense.
- Code should hold behavior; the editor should hold setup
  and data.

[Coding style]
Every single script must be written in the developer's own
coding style (section 5). Follow it exactly.

[Folders]
- Every file lives in the folder of its system. No loose files.
- A folder holds either subfolders or files, never both
  (so base scripts go in a "base" folder next to content folders).
- Exception: godot/test.tscn + test.gd sit in the project root on
  purpose. Main scene, used to test new stuff. Q cycles the test
  weapons (weapons list), keys 1-7 = new item of that rarity
  (level 0, random attributes), E level up, R upgrade rarity,
  C combat level +1, G start next wave, V show/hide attribute panel
  (gray number = roll quality, specials in rarity color),
  X reroll attributes. The starting item rolls attributes on start.
  Has a Camera2D, two hit dummies (top right, out of the paths),
  labels (UpgradeLabel shows level, combat level, damage; WaveLabel),
  a PathNetwork (PathWest on; PathBranch + PathNorth turned on by
  wave 2) and a WaveManager with 3 waves. enemySpriteScales and
  enemyColors (test.gd) size and tint enemies ONLY in the test
  scene: enemy scenes keep unscaled placeholder sprites on purpose
  (real size-appropriate sprites come later).

[Other]
- No comments in code unless the developer asks.
- No test files unless the developer asks, or it is truly
  needed to protect the project.
- No extra scenes or code beyond what the task needs.

Renderer:       Mobile

                integer scaling (pixels always scale evenly)
Textures:       Nearest filter by default (sharp pixels)

This handout:   ./HANDOUT.txt   (project root, outside godot/)
Godot exe:      D:\steam\steamapps\common\Godot Engine\godot.windows.opt.tools.64.exe

                (public, branch main, root = this folder)

- Every push to main runs .github/workflows/web.yml: it downloads
  Godot + web templates, exports preset "Web" (export_presets.cfg,
  thread support off so it runs on GitHub Pages) and deploys it.
  When upgrading Godot, change GODOT_VERSION in that file.

  Mobile. Check new shaders/effects in the web build too.
- Local web exports go to build/ (git ignored).
- Physics interpolation is on (smooth movement on high refresh
  screens). Cameras must use process_callback Physics or Godot warns.
  Move things in _physics_process; teleports need
  reset_physics_interpolation().
- The developer usually has the editor open. After editing
  project.godot or moving files, tell them to use
  Project > Reload Current Project, and never save stale tabs.
- Verify changes headless on a scratch copy of the project, never
  inside it. To catch warnings: set every
  debug/gdscript/warnings/* that is 1 to 2 in the copy, then load
  all scripts. The developer wants zero errors and zero warnings.


--------------------------------------------------------------
5. CODING STYLE
--------------------------------------------------------------
Example: godot/weapons/base/weapon.gd

- Line 1-2: extends, then class_name (if any). Then 2 blank lines.
- Signals first, then variables in this order:
  const > @export > @onready > normal var.
  Same kind stays together; 1 blank line when the kind changes.
- Many variables on one topic: group them by topic, each group
  uses the same order, then the next topic starts.
- After the variables: 1 blank line, then  #------------------------#
  then 1 blank line. A label goes in the middle of the dashes,
  e.g.  #-------MOVEMENT VARIABLES-------#
- Variables and parameters: camelCase  (maxHealth, newState)
- Functions and signals: snake_case  (take_damage, health_changed)
- Own functions never start with _. Only Godot's built-in
  functions do (_ready, _physics_process).
- Types written with spaces: var speed : float = 80.0
- 1 blank line between functions. Tabs for indentation.
- class_name always ends with "Class": PlayerClass, WeaponClass.
  (Node names in scenes do not: nodes stay "Player", "Weapon".)


--------------------------------------------------------------
6. SYSTEMS BUILT SO FAR
--------------------------------------------------------------
[Player]  godot/player/base/player.tscn + player.gd  (PlayerClass)
- Base player = the player with no class chosen.
  Classes = inherited scenes of player.tscn.
- Scene: Visuals/Sprite2D (body), HandPivot/Hand/Sprite2D (hand),
  AnimationPlayer, CollisionShape2D, components, StateMachine
  (MoveState, AttackState).
- Exports: image, handImage, weaponItem, flipSpeed,
  healthComponent, movementComponent. No image/handImage = placeholders.
- weaponItem (WeaponItemClass) is equipped on _ready.
  equip_weapon(item) swaps items; spawn_weapon() respawns the
  weapon node from the item into HandPivot/Hand. The player listens
  to the item's changed signal and respawns only when its rarity
  changed (level/combat level are read live).
  "weapon" = current weapon node (var).
- HandPivot rotates to the mouse, so the hand circles the player.
  The hand never flips. The weapon mirrors vertically (scale.y -1)
  while pointing right (WeaponClass.update_flip), so sprite tip
  slopes face down on both sides.
- Idle: weapon Visuals held upright (WeaponClass holdAngle, -100 =
  up tilted back, mirrored on the left; holdSpeed). Only visual:
  attacks still aim at the mouse. Attacks that move Visuals set
  weapon.isSwinging while they do (SlashAttack returns to
  get_hold_rotation() after the swing). Flip is locked while
  swinging.
- Swings move the whole arm: SlashAttack tweens weapon.swingRotation
  (Visuals stay at 0) and the player adds it to HandPivot rotation.
  Aim = attack global_rotation - weapon.swingRotation. Any future
  wielder must also add swingRotation to its hand.
- Facing the mouse side flips only the body like a 3D turn:
  player Visuals scale.x slides to +1/-1.
  So never animate player Visuals scale; animate its Sprite2D.
- Animations: idle (subtle stretch), walk (quick side-to-side
  rotation). Sprite2D origin is at the feet (offset -8).
  States pick the animation (MoveState/AttackState).

[Components]  godot/components/<name>/
- HealthComponentClass: maxHealth. take_damage(), heal().
  Signals: health_changed(currentHealth, maxHealth), died.
- MovementComponentClass: speed, acceleration, deceleration.
  move(body, direction, delta) sets velocity + move_and_slide.
  Unique movement feel: extend it and override move().
- HurtboxComponentClass (Area2D): can be hit. Exports healthComponent,
  statusComponent, showDamageNumbers. take_damage(amount, damageType,
  isCrit) spawns a floating DamageNumber. apply_status(effect) passes
  status effects to its statusComponent (none = ignored).
  knockback(impulse) adds to the parent CharacterBody2D velocity.
- StatusComponentClass (Node): active status effects on a target.
  Exports hurtbox (effects deal damage through it, so damage numbers
  work), sprite (the target's main Sprite2D, used by overlay visuals
  like frost) and visualParent (default: its parent). Many different effects
  at once, keyed by effectName; the same name again = refresh
  (longest duration, burn keeps highest damage). Visual particles
  stop emitting and are freed 1s after the effect ends.
  Signals: effect_added, effect_removed. has_effect(name).
- HitboxComponentClass (Area2D): damages hurtboxes it touches.
  Exports damage, damageType, critChance, critMultiplier (crit is
  rolled per hit), maxHits (0 = unlimited). Attacks fill these via
  WeaponClass.setup_hitbox(). Hurtboxes entering in the same frame are
  collected and hit nearest first (deferred), so maxHits picks the
  closest enemies. damageModifier (Callable, set by the weapon) changes
  damage per target before crit (first strike etc.). hitCount must be
  reset when a hitbox is reused (MeleeAttack does).
  Signal: hit(hurtbox, damage) (emitted in the deferred resolve).

[State machine]  godot/components/state_machine/
- StateMachineClass node: children are states. initialState export.
  Runs the current state's physics_update().
- StateClass: enter(), exit(), physics_update(delta).
  Switch with stateMachine.change_state(otherState), where
  otherState is an @export StateClass set in the inspector.
- States get their character with:
  @onready var player : PlayerClass = owner
- Player states: godot/player/states/
  MoveState -> AttackState while "attack" is held (needs weapon).
  AttackState: canMove export, back to MoveState on release.

[Weapons]  godot/weapons/
- WeaponClass (base/weapon.gd): a scene per weapon. Root Node2D,
  child Node2D "Visuals" with the Sprite2D (attacks may rotate
  Visuals to swing). Grip at (0,0), weapon points right (+x).
  Exports rarity, damage, attackCooldown, damageType, critChance,
  critMultiplier, knockback, effects, fixedAttributes (always on the
  item, for artifacts).
  attack() stores aimRotation, runs perform() on EVERY child attack
  (get_attacks()), then effects and attributes on_attack, then waits
  get_attack_cooldown(). The hand rotates it, so child nodes aim too.
  wielder = the player holding it (set by equip_weapon).
  item = the WeaponItemClass it was spawned from (null = none).
  attributes = the item's AttributeRollClass list (copied on create).
  get_power_multiplier() = rarity x item level x combat level x
  (1 + Damage attribute). get_damage() = damage x power.
  Stat getters (base export + attributes): get_crit_chance(),
  get_crit_multiplier(), get_attack_cooldown(), get_knockback(),
  get_status_power() (power x (1 + Status Damage)), get_stat(stat).
  setup_hitbox(hitbox, damageMultiplier) fills any hitbox/projectile.
  register_hit: effects on_hit, attributes on_hit, knockback, then
  applies the statuses collected with add_hit_status(status): the same
  effectName from several sources is combined into ONE application
  (fire sword burn + Burn attribute = one stronger burn).
  get_color() = first attack's color (slash = blade color).
  A weapon scene is the TEMPLATE; its damage is the damage at
  upgrade level 0, combat level 1, rarity multiplier 1.
- Weapon scenes live by category: weapons/melee/slashing/
  (png + tscn together). Hammers etc. get their own category.
  Existing: wooden_sword, iron_sword, spear (360 spin), flame_sword
  (physical hits + fire effect; only the burn deals fire damage),
  frost_scythe (physical hits + frost effect).
- Attacks (attacks/<type>/): nodes placed inside the weapon scene.
  Node position = where the attack comes from.
  * AttackClass (base/): damageMultiplier, weapon. perform(),
    get_attack_type(), get_color().
    Hits must be passed to register_hit(hurtbox, damage) so
    effects hear about them (connect hitbox/projectile "hit").
  * MeleeAttackClass (melee/): plain hitbox attack, no visuals.
  * ProjectileAttackClass (projectile/): projectileScene,
    projectileCount, spreadAngle.
  * SlashAttackClass (slash/): see [Slash] below.
  Attack types = AttackTypeClass .tres in attacks/types/ (slash,
  melee, projectile). Each attack script returns its type from
  get_attack_type() (const ATTACK_TYPE preload). Attributes use them.
  New attack type = script extending AttackClass, override perform()
  and get_attack_type(), + a new .tres in attacks/types/.
  Each attack type with visuals (hammer smash etc.) gets its own
  style resource on RarityClass, like slashStyle.
- ProjectileClass (projectiles/base/): script for projectile scenes
  (Area2D root, extends HitboxComponentClass). speed, lifetime, color
  (set by the spawner). Destroyed on hit or on a wall.
  projectiles/slash_wave/: SlashWaveClass, glowing crescent drawn in
  _draw + trail, hit spark on hit, fades out, maxHits 1.
- RarityClass (rarities/): Resource with rarityName, color,
  damageMultiplier, attributeSlots, maxSpecialAttributes, nextRarity,
  slashStyle (embedded), enchantStyle, effects. nextRarity = what a
  rarity upgrade turns it into (common > ... > mythic; mythic and
  artifact have none).
  Rarity slash range bonuses were reduced (felt op): sizeMultiplier
  1 / 1.02 / 1.04 / 1.06 / 1.08 / 1.11 / 1.15, curveBonus epic 5,
  legendary 10, mythic 15, artifact 25.
  New rarity = duplicate a .tres (embedded style is copied too).
  Final damage = weapon damage x rarity x upgrade level x combat
  level x attack damageMultiplier.
- Effects (effects/, base script in effects/base/): custom behavior
  for weapons AND rarities. WeaponEffectClass Resource with
  on_equip(weapon) (in _ready, for weapon visuals), on_attack(weapon)
  and on_hit(weapon, hurtbox, damage). New behavior = script extending
  WeaponEffectClass, add it to a weapon's or rarity's effects list.
  A weapon uses its own effects + its rarity's effects.
  Each weapon gets its own copies, so effects may keep variables.
  Set rarity before the weapon enters the tree (effects are
  collected in _ready).
  "hit" is emitted deferred, so on_hit can safely spawn nodes.
- Elemental weapon effects = StatusOnHitEffectClass .tres
  (effects/status_on_hit/): status (StatusEffect added on hit with
  weapon.add_hit_status, scale_power(weapon.get_status_power()) if
  scaleWithPower) and
  auraScene (spawned under the sprite on equip). Aura scenes use
  WeaponAuraClass: any Sprite2D child gets the weapon texture (glow via
  enchant.gdshader), any CPUParticles2D child emits from the blade
  pixels. effects/fire/fire.tres (burn + weapon_flames.tscn),
  effects/frost/frost.tres (frost + weapon_frost.tscn),
  effects/poison/poison.tres (poison + weapon_poison.tscn, no weapon
  uses it by default yet). New element = new aura scene + .tres.
- WeaponClass.get_sprite() = first Visuals Sprite2D.
  WeaponClass.get_pixel_points(texture, bladeOnly) = opaque pixel
  positions for particle emission (bladeOnly keeps the top-right half,
  since sprites are drawn handle bottom-left). Scenes preloaded by
  weapon.gd must not reference WeaponClass (preload cycle), so pass
  data in instead.
- Totally different attacking: new attack type, or extend WeaponClass.

[Weapon items + upgrades]  godot/weapons/base/weapon_item.gd,
                           godot/weapons/upgrades/
- WeaponItemClass (Resource) = ONE owned copy of a weapon: the
  thing inventories, loot drops and saves will hold. Exports
  weaponScene, rarity, level, combatLevel, rarityUpgraded, attributes
  (Array[AttributeRollClass]). Runes go on the item later.
- create_weapon() instantiates weaponScene with item, attributes and
  rarity set.
- level_up() (up to maxLevel), upgrade_rarity() (only at max level,
  only once, needs rarity.nextRarity, resets level to 0, keeps
  attributes and rolls the new slot), upgrade_combat_level(amount),
  randomize_attributes() (fixed + fresh random rolls).
  can_level_up() / can_upgrade_rarity() hold the rules: add coin and
  material checks there later. Every change calls emit_changed().
  The player respawns the weapon when rarity or attributes change.
- get_damage_multiplier() = upgrade level x combat level.
  get_attribute_level() = level (+ maxLevel if rarityUpgraded or the
  rarity has no nextRarity), max get_max_attribute_level() = 30.
- WeaponUpgradesClass (weapon_upgrades.tres, one shared file,
  preloaded by the item as UPGRADES): maxLevel (15), damagePerLevel
  (+5% each). Upgrade costs go here later.

[Attributes]  godot/weapons/attributes/
- AttributeClass (base/attribute.gd) = one attribute definition, a
  .tres in normal/ or special/. Exports attributeName, description
  ("{value}" and other placeholders, % and ° written in the text),
  stat, scaling, attackTypes, special, weight (roll chance weight;
  specials use 0.6, Elemental Power 0.7).
- attackTypes = AttackTypeClass list where it can roll. Empty = every
  attack type. ONE attribute works for many attack types: add the
  type to its list instead of making a copy (e.g. Slash Size is
  [slash]; a future smash just gets added and reads the same stat).
- stat (enum AttributeClass.Stat): NONE, DAMAGE, CRIT_CHANCE,
  CRIT_DAMAGE, ATTACK_SPEED, KNOCKBACK, ATTACK_SIZE, ATTACK_ARC,
  EXTRA_TARGETS, STATUS_DAMAGE. Plain stat attributes need no script:
  code reads weapon.get_stat(stat) where the stat matters (slash reads
  ATTACK_SIZE, ATTACK_ARC, EXTRA_TARGETS). Only ADD new stats at the
  end of the enum (.tres files store the number).
- AttributeScalingClass (base/, embedded in the .tres): minBase,
  maxBase (value at attribute level 0 for the worst/best roll),
  perStep added every levelsPerStep levels, maxValue (0 = no cap),
  percent (0.1 shown as 10), wholeNumber. Rolled bases snap to 0.1%
  (percent), whole numbers or 0.1.
- AttributeRollClass (base/) = one rolled attribute on an item:
  attribute + quality (0-1). get_value(level), get_description(level).
- Behavior hooks (override in a script extending AttributeClass):
  can_roll(weapon, chosen), on_equip(weapon, roll), on_attack(weapon,
  roll), on_hit(weapon, roll, hurtbox, damage), modify_hit_damage(
  weapon, roll, hurtbox, damage), get_description_values(quality,
  level). Definitions are shared: keep no state in them.
  behaviors/: HealthDamageAttributeClass (bonus damage when target
  health is between minHealth and maxHealth), StatusBoostAttributeClass
  (only rolls if the weapon applies a status), StatusAttributeClass
  (element = a StatusOnHitEffect .tres: status damage = weapon damage
  x status power x value, adds the element aura unless the weapon
  already has it, never rolls with a status that cancels another one:
  burn vs frost), LifeStealAttributeClass (heals wielder
  healthComponent), AreaDamageAttributeClass (radius, damages other
  hurtboxes on the same layer + vfx/shockwave), ProjectileAttributeClass
  (projectileScene, countScaling, spreadAngle, fires at aimRotation),
  DoubleStrikeAttributeClass (chance to perform matching attacks again
  after delay).
- AttributePoolClass (pool/attribute_pool.tres, preloaded by the item
  as ATTRIBUTE_POOL): attributes (every rollable attribute),
  maxAttributes (5). roll_attributes(item, kept): weapon
  fixedAttributes first (copied), then kept ones, then random picks
  (weighted, no duplicates, can_roll, specials only up to
  rarity.maxSpecialAttributes; fixed specials count too).
  New attribute = .tres (+ behavior script if it does something new)
  and add it to attribute_pool.tres.
- Normal (all attack types unless noted), level 0 worst..best, +step:
  Damage 5-8% +0.5%/lvl, Crit Chance 3-5% +1%/3 lvls, Crit Damage
  15-25% +2%/lvl, Attack Speed 4-6% +0.5%/lvl, Knockback 40-60
  +2/lvl, First Strike (full health) 20-30% +1.5%/lvl, Executioner
  (below 35%) 15-25% +1%/lvl, Elemental Power (status damage, needs a
  status) 10-15% +1%/lvl, Slash Size [slash] 5-8% +0.5%/lvl, Slash Arc
  [slash] 8-12° +1°/lvl, Cleave [slash] +1 target, +1 every 10 lvls,
  max 3.
- Special: Life Steal 1.5-2.5% +0.1%/lvl, Area Damage 25-35%
  +1%/lvl (radius 20), Blade Waves [slash] 30-40% damage +1%/lvl,
  count 1 +1 every 5 lvls max 3, Burn 8-12% damage per tick
  +0.5%/lvl, Frostbite 50-70% +2.5%/lvl, Poison 3-4% per stack
  +0.15%/lvl, Double Strike [slash] 12-18% chance +0.5%/lvl.
- SlashAttack maxTargets (3, spear 4) + Cleave = enemies per slash.

[Combat level]  godot/combat_level/
- CombatScalingClass (combat_scaling.tres, preloaded by the item as
  COMBAT_SCALING): growthPerLevel (0.1). get_multiplier(combatLevel)
  = (1 + growth) ^ (combatLevel - 1), so combat level 1 = x1 and
  every level is +10% on top of the last.
- Enemies (not built) must scale health/damage with the SAME
  get_multiplier(), so a weapon matching the island's combat level
  always feels the same, and old low level weapons fall behind.

[Enchant]  godot/weapons/enchant/
- RarityClass enchantStyle (EnchantStyleClass, embedded): glowStrength,
  glowSize, pulseSpeed, particleAmount. Empty = no enchant
  (common-epic). Legendary, mythic, artifact have one.
  Enchant draws behind the weapon sprite (show_behind_parent);
  weapon effect visuals (flames) draw on top (z_index 1).
- WeaponClass.add_enchant() puts enchant.tscn under the first
  Visuals Sprite2D: Glow (enchant.gdshader: slow pulsing halo,
  additive, Linear; no shimmer band, the developer disliked it) and
  Particles (tiny, short-lived
  CPUParticles2D emitted from the sprite's opaque pixels, world
  coords so they trail). Color = rarity color.

[Slash]  godot/weapons/attacks/slash/
- SlashAttackClass node in a weapon: radius (middle of the swept
  band, from wielder center), size (band thickness), curve (arc
  degrees), maxTargets, raritySizeGrowth, styleOverride (custom style,
  e.g. artifacts).
  Each attack: spawns ONE slash.tscn as child of the wielder, swings
  weapon Visuals over 70% of duration, alternates swing direction.
- Size = (1 + (style.sizeMultiplier - 1) x raritySizeGrowth) x
  (1 + Slash Size attribute). raritySizeGrowth 1 = normal, higher =
  grows more per rarity (spear uses 2.5).
  Curve = curve + style.curveBonus + Slash Arc (max 360).
  Targets = maxTargets + Cleave (hitbox maxHits, nearest first).
- Curve 360 = full spin: slash and weapon start and end at the aim
  direction, hitbox is a full circle.
- Style = styleOverride, else weapon.rarity.slashStyle.
- SlashStyleClass (Resource): duration, sizeMultiplier, curveBonus,
  trail, glow, core, tipGlow, streaks, chromaticAberration,
  orbAmount, hitSparkSize, hitSparkAmount,
  screenShake, hitStop.
- screenShake (2.0) and hitStop (0.04) are capped at epic: legendary+
  use the same. More shake felt like too much, more hit stop froze
  the game up to 20% of the time while attacking and felt laggy.
- Look = ONE filled crescent (like Terraria Cooler Weapon Effects),
  drawn by slash.gdshader on a MeshInstance2D arc mesh built in code.
  The developer disliked stacked lines/echo arcs: never go back to
  layering separate arcs. Higher rarity = longer trail, glow, white
  rim, streaks (noise texture), rim-only RGB fringe, wider curve.
- Shader uniforms set from slash.gd; "head" (0-1) is the blade
  position along the arc, "trail" the fading length behind it.
  ShaderMaterial is local_to_scene so every slash has its own.
- Colors: taken automatically from the weapon's Visuals Sprite2D
  (dark/main/light by luminance, cached per texture), or from
  SlashAttack colorTexture if set (spear uses iron_sword.png).
- Particles: none on the arc. Glowing orbs spawn only at the HIT
  location (hit_spark scene). No dust anywhere: the developer removed
  it, it looked out of place.
- Own HitboxComponent: sector polygon from radius/size/curve, mask
  Enemy Hurtbox, active first 60% of duration.
  On hit: hit spark + register_hit per enemy; GameFeel hit stop +
  shake only once per slash (hitFeelPlayed), however many enemies.
- slash.gd types "attack" as AttackClass on purpose: typing it as
  SlashAttackClass creates a preload cycle (slash_attack.gd preloads
  slash.tscn) and breaks opening slash.tscn.
- Smooth VFX nodes use texture_filter Linear (project default is
  Nearest). Pixel art VFX stays Nearest.
- Shaders follow the same style (2 blank lines after the header,
  camelCase uniforms, //------------------------// separator).

[VFX]  godot/vfx/
- hit_spark/: HitSparkClass star burst (drawn spikes + flash +
  spark particles + glowing orbs). Vars: color, strength,
  sparkAmount, orbAmount, angle.
- shockwave/: ShockwaveClass expanding ring + soft flash (radius,
  color), used by Area Damage. Kept subtle: several at once must not
  blow out to white.

[Status effects]  godot/status_effects/
- StatusEffectClass (base/): Resource with effectName, duration,
  tickInterval, visualScene (spawned on the target while active),
  interactions. on_apply(), on_tick(), on_remove(), refresh(newEffect),
  combine(other) (merge two of the same effect from ONE hit, e.g. add
  damage), scale_power(multiplier), set_damage(amount) (used by
  status attributes). "status" = the StatusComponentClass it is on.
  Applied copies are duplicated (only exported vars are copied).
  New effect = script extending it + a .tres in its own folder.
- Interactions (expandable): StatusInteractionClass (base/) on an
  effect's interactions list: triggerEffects (effect names being
  applied), triggerDamageTypes (damage taken), blockTriggerEffect
  (stop the incoming effect). trigger(effect) = what happens to the
  effect that owns it. RemoveInteractionClass (interactions/) removes
  it. New reaction (bonus damage, spread, ...) = script extending
  StatusInteractionClass, add it in the .tres. The interaction lives
  on the effect that gets affected.
- Burn (burn/): BurnEffectClass damagePerTick, damageType (fire).
  burn.tres = 3s, tick 0.5s, burn_flames.tscn on the target.
  Removed (and blocks it) when Frost is applied; ice damage removes it.
- Frost (frost/): FrostEffectClass build-up. Each hit = 1 stack
  (frost_visual.tscn: FrostVisualClass copies status.sprite into an
  Overlay with frost_overlay.gdshader that freezes the sprite from the
  bottom up, fully frozen at stacksToProc - 1, + mist/snow), at
  stacksToProc (4) = frostbite:
  frostbiteDamage (20, ice = blue numbers) + frostbite_explosion.tscn
  (flash, icicle.png particles with icicle.gdshader glow halo, ice
  blue shards in normal blend; Timer frees it),
  then removed. Build-up clears after duration (4s) without hits.
  Removed (and blocks it) when Burn is applied; fire damage removes it.
- Poison (poison/): PoisonEffectClass damagePerStack, maxStacks (5),
  damageType (poison). Every hit adds a stack and refreshes (4s,
  tick 0.5s); tick damage = damagePerStack x stacks.
  poison_bubbles.tscn on the target. No interactions.
- Targets need a StatusComponent (+ hurtbox statusComponent set) to
  receive effects. Test dummies have one.

[Damage types]  godot/damage/
- DamageTypeClass (base/damage_type.gd): typeName, color, critColor.
- New damage type = new .tres in damage/types/ (physical, fire, ice,
  poison exist). Set it on a weapon (damageType).
- vfx/damage_number/: DamageNumberClass pops, rises, fades. Crit =
  bigger, critColor, "!" suffix. Text via NumberFormatClass.

[Utils]  godot/utils/
- NumberFormatClass.format(value) (static): whole number below
  100000 ("99999"), above that max 2 decimals + suffix k/m/b/t/q
  ("100k", "125.33k", "7.32m", "5b"). Use it for every big number
  shown to the player (damage, later coins, stats).

[GameFeel]  godot/autoload/game_feel.gd  (autoload "GameFeel")
- hit_stop(seconds): Engine.time_scale = 0, restored by real time.
  Weapon cooldown timers ignore time scale, so hit stop does not
  slow the attack rhythm.
- shake(strength): shakes the active Camera2D offset. Needs a camera.
- Autoloads do not exist in --script test runs; test by running a
  harness scene normally instead.

[Paths]  godot/paths/
- Level setup: a PathNetwork node (PathNetworkClass, base/) with
  EnemyPath children (EnemyPathClass, extends Path2D). Draw the curve
  with the Path2D tools: first point = start, last point = end.
  Paths must be children of a PathNetwork.
- EnemyPath exports: active (off = no pulse, no enemies branch into or
  merge into it; setter emits active_changed), branchFrom (this path
  starts on that path at the closest point), mergeInto (this path's
  end joins that path at the closest point, enemies continue on it),
  cornerRadius. Start/end are snapped onto the connected path, so
  placing them roughly is enough.
- route = the Curve2D enemies and visuals use: the drawn curve with
  rounded corners (cornerRadius). get_length(), get_global_point(d),
  get_closest_distance(point). branches = paths branching off it.
- Pulse animation (between waves and at level start): purple glowing
  pulse travels from spawn starts through branches and merges, leaves
  an afterglow, then fades and repeats (network clock, all paths in
  sync). play_preview() / stop_preview(). During a wave (stopped) the
  whole active network stays visible, grayed out and transparent
  (waveOpacity). playOnStart export.
- Look + timing: pulse/path_pulse_style.tres (PathPulseStyleClass),
  the network's style export (default = that file).
- pulse/path_pulse.tscn: spawned per path at runtime. Line
  (MeshInstance2D, strip mesh built in code, path_pulse.gdshader
  additive), head halos drawn in _draw (headTexture), StartDot and
  EndDot (path_dot.tscn: glow, core, ring pop; shown when the pulse
  reaches them). Only spawn starts and final ends get a dot: dots on
  connection points (branch starts, merge ends) are removed, the
  developer thought they looked off.
  Mesh inner width is limited around bends so it never folds (the
  developer saw spiky artifacts before that).
- Draw layer: path pulse is z_index -5 (absolute). Ground/tilesets
  must be below that (e.g. -10); characters stay at 0.

[Enemies]  godot/enemies/
- EnemyClass (base/enemy.gd + enemy.tscn, CharacterBody2D, layer
  Enemy): image export (empty = placeholder), flipSpeed,
  healthComponent, movementComponent, pathFollowComponent. Visuals/
  Sprite2D like the player, walk animation, Hurtbox (Enemy Hurtbox) +
  StatusComponent. Health x COMBAT_SCALING.get_multiplier(combatLevel)
  (combatLevel set by the WaveManager). died -> die() (queue_free),
  reached_end -> on_reached_end() (queue_free for now, no crystal yet).
  Signals connected in the scene.
- New enemy = inherited scene of enemy.tscn, set stats on the
  components. basic/: regular_enemy (40 hp, speed 22), big_enemy
  (160 hp, speed 12, bigger hurtbox), small_enemy (10 hp, speed 40,
  smaller hurtbox).
- PathFollowComponentClass (components/path_follow/): start(path,
  body) places the body at the path start. get_direction(body) moves a
  target point along the route, lookAhead px ahead of the body, and
  returns the direction to it (MovementComponent does the moving, so
  knockback/blocking keep working). At a branch point it picks
  randomly between staying and every active branch there. Merges
  continue on mergeInto. reached_end signal.

[Waves]  godot/waves/
- WaveManager node (WaveManagerClass): exports pathNetwork,
  enemyParent (empty = current scene), combatLevel. Children = Wave
  nodes in order. start_next_wave(). Signals wave_started,
  wave_finished, enemy_spawned(enemy). A wave ends when everything
  spawned and every enemy is gone.
- Wave node (WaveClass): activatePaths. Children = SpawnGroup nodes.
  When a wave is NEXT (level start / previous wave done) its
  activatePaths and every path its SpawnGroups use turn on, then the
  path preview plays.
- SpawnGroup node (SpawnGroupClass): enemyScene, path, count,
  interval, delay.

[Collision layers]
1 World, 2 Player, 3 Enemy, 4 Player Hurtbox, 5 Enemy Hurtbox.
Hitboxes/projectiles: layer none, mask the target hurtbox layer.
Projectiles also mask World. Hurtboxes: own layer, mask none.

Input actions: left, right, up, down (WASD), attack (left mouse).
