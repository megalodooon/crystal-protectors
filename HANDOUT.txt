--------------------------------------------------------------
1. WHAT WE ARE MAKING
--------------------------------------------------------------
A 2D pixel art game inspired by Dungeon Defenders: players
protect a crystal from waves of enemies using heroes and
placeable defenses. Stays pixel art (vector art was considered
and rejected). Effects may be smooth and glowy on top of the
pixel art, like the Terraria "Cooler Weapon Effects" mod:
the developer wants attacks to feel very smooth and juicy.

Rarities: common > uncommon > rare > epic > legendary > mythic
> artifact. Mythic = exceedingly rare, endgame. Artifact =
custom weapons with insane abilities, incredibly rare.
Higher rarity = cooler attack effects.

Weapon progression (agreed, like Dungeon Defenders 2):
- Every weapon levels 0 to 30. Levels raise damage (+8% each) and
  attributes (attribute level = weapon level).
- From level 15 a weapon may upgrade its rarity ONCE (common wooden
  sword -> uncommon). The level is KEPT. Leveling on without the
  rarity upgrade is always allowed (missing requirements never block
  leveling). Costs coins + crafting materials (not implemented yet).
- Attributes: random from a pool, values roll too (quality 0-1).
  Slots: common 1, uncommon 2, rare 3, epic 4, legendary+ 5 (max 5).
  Special attributes (life steal, blade waves, burn...) only on
  legendary+: legendary up to 1, mythic up to 2, artifact up to 2.
  Artifacts = custom fixed attributes + rollable ones.
  Rarity upgrade keeps all attributes and rolls the new slot.
- Combat level does NOT affect attributes. Some attributes step
  every few levels with a cap (blade waves: +1 at level 15, max 2).
- Combat level (separate from upgrade level): about 20 combat levels
  from the first island to the end. Later islands drop higher combat
  level gear and have stronger enemies (more health, and a small,
  slowly growing chance to spawn with a modifier like Fortified).
  Old weapons can have their combat level raised at the blacksmith.
- Main elements (developer): fire, frost, poison, lightning, water.
- Hub area: blacksmith, shops, NPCs and other systems (not built).

The full vision belongs to the developer and is not written
down yet. Fill in details here as they get decided. Do not
invent design details that have not been agreed on.

--------------------------------------------------------------
3. RULES
--------------------------------------------------------------
[Godot-first, not code-first]
Do not do things from code when it is not necessary. Use the
Godot node / scene / resource / inspector system instead:
- Build structure as nodes and scenes in the editor, not by
  creating nodes in code.
- Store data and configuration in Resources (.tres) and
  @export variables, not hardcoded values.
- Connect signals in the editor where it makes sense.
- Code should hold behavior; the editor should hold setup
  and data.

[Coding style]
Every single script must be written in the developer's own
coding style (section 5). Follow it exactly.

[Folders]
- Keep the folder count LOW (developer: too many folders is messy).
  One folder per system, files flat inside it. No folder per item
  (no vfx/nova/nova.tscn: it is vfx/effects/nova.tscn). Only split
  a system when it has clearly different groups (attributes: base,
  behaviors, normal, special, synergy).
- A folder holds either subfolders or files, never both.
- Layout (godot/):
  core/ (GameFeel + Vfx autoloads, NumberFormat, combat scaling),
  components/, damage/ (damage type script + types),
  enemies/ (enemy scenes + modifier chances), paths/, player/,
  waves/ (wave manager, waves, spawn groups, portal), status_effects/ (base, fire, frost, poison, lightning,
  water, debuffs, modifiers), towers/, ui/ (HUD pieces), vfx/ (base = parts, shared =
  textures and curves, effects = one-shot effect scenes, buffs),
  weapons/ (attacks, attributes/{base, behaviors, normal, special, synergy},
  auras, base, effects, enchant, projectiles, rarities, slashing,
  spawns).
- Moving files: move the file with its .uid/.import and replace the
  res:// path in every .tscn/.tres/.gd/.godot file.
- Exception: godot/test.tscn + test.gd sit in the project root on
  purpose. Main scene: a FULL LEVEL (10 waves) that every system can be
  tested inside, not a bare sandbox. Q cycles the test
  weapons (weapons list), keys 1-7 = new item of that rarity
  (level 0, random attributes), E level up, R upgrade rarity,
  C weapon combat level +1, Z enemy combat level +1 (label shows the
  modifier chance), T cycles a test element on the held weapon
  (testElements: fire, frost, poison, lightning, water), G start next
  wave (auto waves also start by countdown), V show/hide attribute panel (5 bars in front = roll quality,
  specials in rarity color, synergies in gold with a +), X reroll
  attributes, Y artifact with a random synergy (its required specials +
  random rest). The starting item
  rolls attributes on start.
  B cycle the tower to build (ghost follows the mouse), F build it,
  U / H / J upgrade, repair and sell the tower under the mouse (a
  tooltip next to it shows the tier and what each key costs), M +100
  mana, F1 hide/show the whole HUD.
  Map is 512x288 (bigger than the screen): Ground (tiled noise
  texture, z -10), Camera2D inside Player (smoothing, limits = map).
  Two hit dummies above the player start, out of every lane.
  HUD: CanvasLayer/HUD Control holds a Theme (default_font_size 5,
  Label line_spacing 0): change the text size of ALL labels there.
  Labels: RarityLabel, WaveLabel (countdown for auto waves),
  UpgradeLabel (anchored bottom), AttributePanel.
  PathNetwork, 3 portals (the most a level should have):
  * PathWest (on from the start, portal top left) runs right, down and
    right again to the centre.
  * PathNorth (portal top middle, first used in wave 2) runs down,
    right, down and left to the centre.
  * PathEast (portal bottom right) is LOCKED until wave 5: it is
    inactive and its portal shows nothing until wave 5 is next, then it
    opens and merges into PathNorth.
  * Shortcut branches off PathWest and merges back into it, turned on
    by wave 3, so enemies may skip the long corner.
  Both main lanes end on the SAME point in the map centre (256, 160),
  which is where the crystal goes. The player starts just above it, so
  the whole defense area is one screen.
  WaveManager with 10 waves, every wave a different pressure and a
  rising combat level: 1 Scouts (one lane), 2 Pincer (second lane),
  3 Shortcut (branch opens), 4 Swift Rush (58 fast enemies, auto
  start), 5 The Breach (east portal opens + a Warden with health x8),
  6 Ironhide (Fortified brutes), 7 Swarm (88 enemies, the crowd test),
  8 Undying (Regenerating), 9 Siege (all three lanes), 10 Warlord
  (boss with health x20, then a Last Stand group after it dies).
  436 enemies in total, effective health per wave roughly
  400 / 820 / 1560 / 1500 / 2760 / 2690 / 2690 / 3230 / 4900 / 10050.
  Frame cost of the worst waves (Compatibility renderer, nothing
  attacking): wave 7 peak 88 alive 0.9 ms median / 1.9 ms worst 1%,
  wave 10 1.2 ms / 2.8 ms. enemySpriteScales and
  enemyColors (test.gd) size and tint enemies ONLY in the test
  scene: enemy scenes keep unscaled placeholder sprites on purpose
  (real size-appropriate sprites come later).

[Other]
- No comments in code unless the developer asks.
- No test files unless the developer asks, or it is truly
  needed to protect the project.
- No extra scenes or code beyond what the task needs.

                integer scaling (pixels always scale evenly)
Textures:       Nearest filter by default (sharp pixels)
Godot project:  ./godot/   (project.godot lives here)
This handout:   ./HANDOUT.txt   (project root, outside godot/)
Godot exe:      D:\steam\steamapps\common\Godot Engine\godot.windows.opt.tools.64.exe

                (public, branch main, root = this folder)

- Every push to main runs .github/workflows/web.yml: it downloads
  Godot + web templates, exports preset "Web" (export_presets.cfg,
  thread support off so it runs on GitHub Pages) and deploys it.
  When upgrading Godot, change GODOT_VERSION in that file.

  Mobile. Check new shaders/effects in the web build too.
- Local web exports go to build/ (git ignored).
- Physics interpolation is on (smooth movement on high refresh
  screens). Cameras must use process_callback Physics or Godot warns.
  Move things in _physics_process; teleports need
  reset_physics_interpolation().
- The developer usually has the editor open. After editing
  project.godot or moving files, tell them to use
  Project > Reload Current Project, and never save stale tabs.
- Verify changes headless on a scratch copy of the project, never
  inside it. To catch warnings: set every
  debug/gdscript/warnings/* that is 1 to 2 in the copy, then load
  all scripts. The developer wants zero errors and zero warnings.


--------------------------------------------------------------
5. CODING STYLE
--------------------------------------------------------------
Example: godot/weapons/base/weapon.gd

- Line 1-2: extends, then class_name (if any). Then 2 blank lines.
- Signals first, then variables in this order:
  const > @export > @onready > normal var.
  Same kind stays together; 1 blank line when the kind changes.
- Many variables on one topic: group them by topic, each group
  uses the same order, then the next topic starts.
- After the variables: 1 blank line, then  #------------------------#
  then 1 blank line. A label goes in the middle of the dashes,
  e.g.  #-------MOVEMENT VARIABLES-------#
- Variables and parameters: camelCase  (maxHealth, newState)
- Functions and signals: snake_case  (take_damage, health_changed)
- Own functions never start with _. Only Godot's built-in
  functions do (_ready, _physics_process).
- Types written with spaces: var speed : float = 80.0
- 1 blank line between functions. Tabs for indentation.
- class_name always ends with "Class": PlayerClass, WeaponClass.
  (Node names in scenes do not: nodes stay "Player", "Weapon".)


--------------------------------------------------------------
6. SYSTEMS BUILT SO FAR
--------------------------------------------------------------
[Player]  godot/player/player.tscn + player.gd  (PlayerClass)
- Base player = the player with no class chosen.
  Classes = inherited scenes of player.tscn.
- Scene: Visuals/Sprite2D (body), HandPivot/Hand/Sprite2D (hand),
  AnimationPlayer, CollisionShape2D, components, StateMachine
  (MoveState, AttackState).
- Exports: image, handImage, weaponItem, flipSpeed,
  healthComponent, movementComponent. No image/handImage = placeholders.
- weaponItem (WeaponItemClass) is equipped on _ready.
  equip_weapon(item) swaps items; spawn_weapon() respawns the
  weapon node from the item into HandPivot/Hand. The player listens
  to the item's changed signal and respawns only when its rarity
  changed (level/combat level are read live).
  "weapon" = current weapon node (var).
  Every physics frame movementComponent.speedMultiplier = 1 + weapon
  MOVE_SPEED stat (Swiftness, Adrenaline buff).
- HandPivot rotates to the mouse, so the hand circles the player.
  The hand never flips. The weapon mirrors vertically (scale.y -1)
  while pointing right (WeaponClass.update_flip), so sprite tip
  slopes face down on both sides.
- Idle: weapon Visuals held upright (WeaponClass holdAngle, -100 =
  up tilted back, mirrored on the left; holdSpeed). Only visual:
  attacks still aim at the mouse. Attacks that move Visuals set
  weapon.isSwinging while they do (SlashAttack returns to
  get_hold_rotation() after the swing). Flip is locked while
  swinging.
- Swings move the whole arm: SlashAttack tweens weapon.swingRotation
  (Visuals stay at 0) and the player adds it to HandPivot rotation.
  Aim = attack global_rotation - weapon.swingRotation. Any future
  wielder must also add swingRotation to its hand.
- Facing the mouse side flips only the body like a 3D turn:
  player Visuals scale.x slides to +1/-1.
  So never animate player Visuals scale; animate its Sprite2D.
- Animations: idle (subtle stretch), walk (quick side-to-side
  rotation). Sprite2D origin is at the feet (offset -8).
  States pick the animation (MoveState/AttackState).

[Components]  godot/components/  (one script per component, flat)
- HealthComponentClass: maxHealth. take_damage(), heal().
  Signals: health_changed(currentHealth, maxHealth), died.
- MovementComponentClass: speed, acceleration, deceleration,
  statusComponent (optional: slow/stun slow it down; enemies have it).
  speedMultiplier var (set by the owner, e.g. player). get_speed() =
  speed x speedMultiplier x status speed multiplier.
  move(body, direction, delta) sets velocity + move_and_slide.
  Unique movement feel: extend it and override move().
- HurtboxComponentClass (Area2D): can be hit. find_in_shape(world, shape,
  transform, layer) = any shape query (beams). lastHitOverkill = damage
  past 0 on the killing hit (Overflow). displace(motion) moves the body
  with move_and_collide (Singularity pull). Damage taken is passed to
  every status: StatusEffectClass on_damage_taken(amount, type) (Doom),
  get_remaining_damage() (burn, poison, shock: Catalyst). Exports healthComponent,
  statusComponent, showDamageNumbers. take_damage(amount, damageType,
  isCrit) multiplies by the statuses' damage taken multiplier for that
  damage type (Sunder, Wet vs lightning, Fortified) and shows a
  floating damage number (Vfx.show_damage_number). static
  find_in_radius(world, center, radius, layer, maxTargets) = hurtboxes
  in a circle, only the nearest maxTargets when > 0 (attributes and
  Shock use it). static find_overlapping(area, maxTargets) = the same
  for an Area2D (blade storm, zones). apply_status(effect) passes
  status effects to its statusComponent (none = ignored).
  knockback(impulse) adds to the parent CharacterBody2D velocity.
  is_dead() = health at 0. take_damage records lastHitKilled (this
  damage brought it to 0) and lastHitCrit, read by register_hit.
- StatusComponentClass (Node): active status effects on a target.
  Exports hurtbox (effects deal damage through it, so damage numbers
  work), sprite (the target's main Sprite2D, only used by the frost
  overlay) and visualParent (default: its parent). Many different effects
  at once, keyed by effectName; the same name again = refresh
  (longest duration, burn keeps highest damage) + pulse() on a
  StatusVisualClass visual. When the effect ends: stop() (or particles
  stop emitting) and the visual is freed 1s later.
  Signals: effect_added, effect_removed. has_effect(name).
  get_harmful_effects() = active effects that are not beneficial
  (Contagion and Opportunist use it, so enemy modifiers never count).
  get_damage_taken_multiplier(damageType) / get_speed_multiplier()
  multiply the values of every active effect.
- HitboxComponentClass (Area2D): damages hurtboxes it touches.
  Exports damage, damageType, critChance, critMultiplier (crit is
  rolled per hit), maxHits (0 = unlimited). Attacks fill these via
  WeaponClass.setup_hitbox(). Hurtboxes entering in the same frame are
  collected and hit nearest first (deferred), so maxHits picks the
  closest enemies. damageModifier (Callable, set by the weapon) changes
  damage per target before crit (first strike etc.). hitCount must be
  reset when a hitbox is reused. Hurtboxes at 0 HP
  are still hit (test dummies reach 0 at high damage; skipping them
  made the slash stop hitting). Kills are counted once via
  lastHitKilled instead.
  Signal: hit(hurtbox, damage) (emitted in the deferred resolve).

[State machine]  godot/components/state.gd, state_machine.gd
- StateMachineClass node: children are states. initialState export.
  Runs the current state's physics_update().
- StateClass: enter(), exit(), physics_update(delta).
  Switch with stateMachine.change_state(otherState), where
  otherState is an @export StateClass set in the inspector.
- States get their character with:
  @onready var player : PlayerClass = owner
- Player states: godot/player/ (move_state.gd, attack_state.gd)
  MoveState -> AttackState while "attack" is held (needs weapon).
  AttackState: canMove export, back to MoveState on release.

[Weapons]  godot/weapons/
- WeaponClass (base/weapon.gd): a scene per weapon. Root Node2D,
  child Node2D "Visuals" with the Sprite2D (attacks may rotate
  Visuals to swing). Grip at (0,0), weapon points right (+x).
  Exports rarity, damage, attackCooldown, damageType, critChance,
  critMultiplier, knockback, effects, fixedAttributes (always on the
  item, for artifacts).
  attack() counts attackCount (+1, first attack = 1), stores
  aimRotation, runs perform() on EVERY child attack (get_attacks()),
  then effects and attributes on_attack, then waits
  get_attack_cooldown() (cooldownId: reset_cooldown() makes the weapon
  ready now and ignores the old timer). The hand rotates it, so child
  nodes aim too. get_origin() = wielder position (or the weapon's).
  get_all_effects() = effects + rarity effects (the templates).
  roll_chance(chance) = randf() < chance x (1 + Effect Chance stat):
  use it for EVERY chance based effect.
  get_area_multiplier() = 1 + Effect Area stat.
  wielder = the player holding it (set by equip_weapon).
  item = the WeaponItemClass it was spawned from (null = none).
  attributes = the item's AttributeRollClass list (copied on create).
  get_power_multiplier() = rarity x item level x combat level x
  (1 + Damage attribute). get_damage() = damage x power.
  Stat getters (base export + attributes): get_crit_chance(),
  get_crit_multiplier(), get_attack_cooldown(), get_knockback(),
  get_status_power() (power x (1 + Status Damage)), get_stat(stat)
  (attribute stats + active buffs).
  setup_hitbox(hitbox, damageMultiplier) fills any hitbox/projectile;
  damage goes through every attribute's modify_attack_damage.
  register_hit: effects on_hit, attributes on_hit, on_crit (if the hit
  crit), on_kill (if this hit killed it), knockback, then applies the
  statuses collected with add_hit_status(status) through
  apply_status(hurtbox, status) (duration x (1 + Status Duration)):
  the same effectName from several sources is combined into ONE
  application (fire sword burn + Burn attribute = one stronger burn).
  Buffs (timed stat bonuses from attributes): add_buff(roll, stat,
  duration, maxStacks) adds a stack and resets the timer, one buff per
  roll (AttributeBuffClass in attributes/base/: roll, stat, stacks,
  timeLeft, value = roll value x stacks). Ticked in _process.
  get_color() = first attack's color (slash = blade color).
  A weapon scene is the TEMPLATE; its damage is the damage at
  upgrade level 0, combat level 1, rarity multiplier 1.
- Weapon scenes live by category: weapons/slashing/ (png + tscn
  together). Hammers etc. get their own folder (weapons/smashing/).
  Existing: wooden_sword, iron_sword, spear (360 spin), flame_sword
  (physical hits + fire effect; only the burn deals fire damage),
  frost_scythe (physical hits + frost effect), dagger (0.18s swing,
  small arc, 25% crit), greatsword (1s swing, 210 deg, long reach),
  war_axe (250 deg sweep, heavy knockback), halberd (long narrow
  thrust plus a weaker sweep behind), storm_glaive (360 spin with
  the lightning effect).
- Attacks (weapons/attacks/): nodes placed inside the weapon scene.
  Node position = where the attack comes from.
  * AttackClass (attack.gd): damageMultiplier, weapon. perform(),
    get_attack_type(), get_color().
    Hits must be passed to register_hit(hurtbox, damage) so
    effects hear about them (connect hitbox/projectile "hit").
  * SlashAttackClass (slash_attack.gd): see [Slash] below. The only
    attack so far (unused melee/projectile attacks were removed).
  Attack types = AttackTypeClass .tres (<name>_type.tres, only
  slash_type.tres now). Each attack script returns its type from
  get_attack_type() (const ATTACK_TYPE preload). Attributes use them.
  New attack type = script extending AttackClass, override perform()
  and get_attack_type(), + a new <name>_type.tres.
  Each attack type with visuals (hammer smash etc.) gets its own
  style resource on RarityClass, like slashStyle.
- ProjectileClass (projectiles/projectile.gd): script for projectile
  scenes (Area2D root, extends HitboxComponentClass). speed, lifetime,
  color (set by the spawner). Destroyed on hit or on a wall.
  slash_wave.tscn: SlashWaveClass, glowing crescent drawn in
  _draw + trail, hit spark on hit, fades out, maxHits 1.
  meteor.tscn: MeteorClass (Meteor attribute).
  spirit_orb.tscn: SpiritOrbClass homing orb (turnSpeed,
  seekRange: turns toward the nearest hurtbox on its mask), glow +
  core + trail, hit spark, fades out.
  projectile.weapon = the weapon that fired it (set by
  ProjectileAttributeClass). spectral_blade.tscn: SpectralBladeClass,
  a spinning ghost copy of the weapon texture that flies out and returns
  to the wielder (hits both ways, ignores walls, afterimages).
  falling_star.tscn = a MeteorClass scene; MeteorClass delay staggers
  drops. MeteorClass moves in _physics_process: moving a node per frame
  while physics interpolation is on makes it stutter (the meteor and
  starfall looked glitchy while falling until this was fixed; life orbs,
  blade storm blades and the crystal sentinel had the same bug).
- Spawns (weapons/spawns/): WeaponSpawnClass (weapon_spawn.gd) base for
  things an attribute summons: radius, duration, value, damage,
  damageType, crit, color, target; tickInterval -> on_tick(), on_end(),
  fade, get_targets(), hit(), spawn_vfx(), refresh(). singularity
  (pulls + damage ticks, collapse vfx), storm_cloud (follows the
  wielder, lightning at random enemies), soul_link (tethers up to 4
  enemies, shares damage through health_changed), crystal_sentinel
  (floating crystal beside the wielder firing spirit orbs).
- RarityClass (rarities/): Resource with rarityName, color,
  damageMultiplier, attributeSlots, maxSpecialAttributes, nextRarity,
  slashStyle (embedded), enchantStyle, effects. nextRarity = what a
  rarity upgrade turns it into (common > ... > mythic; mythic and
  artifact have none).
  Rarity slash range bonuses were reduced (felt op): sizeMultiplier
  1 / 1.02 / 1.04 / 1.06 / 1.08 / 1.11 / 1.15, curveBonus epic 5,
  legendary 10, mythic 15, artifact 25.
  New rarity = duplicate a .tres (embedded style is copied too).
  Final damage = weapon damage x rarity x upgrade level x combat
  level x attack damageMultiplier.
  damageMultiplier (weapons felt way too strong, keep it low): common
  1, uncommon 1.1, rare 1.2, epic 1.35, legendary 1.5, mythic 1.7,
  artifact 2. Rarity power should come from slots and specials more
  than raw damage.
- Effects (effects/, base script weapon_effect.gd): custom behavior
  for weapons AND rarities. WeaponEffectClass Resource with
  on_equip(weapon) (in _ready, for weapon visuals), on_attack(weapon),
  on_hit(weapon, hurtbox, damage) and uses_stat(stat) (lets boost
  attributes like Elemental Power know the weapon benefits). New behavior = script extending
  WeaponEffectClass, add it to a weapon's or rarity's effects list.
  A weapon uses its own effects + its rarity's effects.
  Each weapon gets its own copies, so effects may keep variables.
  Set rarity before the weapon enters the tree (effects are
  collected in _ready).
  "hit" is emitted deferred, so on_hit can safely spawn nodes.
- Elemental weapon effects = StatusOnHitEffectClass .tres
  (effects/status_on_hit_effect.gd): status (StatusEffect added on hit
  with weapon.add_hit_status, scale_power(weapon.get_status_power()) if
  scaleWithPower), chance (per hit; all elements use 0.4, the
  developer wants effects to be a chance, never a guarantee) and
  auraScene (spawned under the sprite on equip).
  effects/: fire.tres (burn + fire_aura), frost.tres (frost +
  frost_aura), poison.tres (poison + poison_aura), lightning.tres
  (shock + electric_aura), water.tres (wet + water_aura, no power
  scaling: wet deals no damage). Flame sword and frost scythe use fire
  and frost; the others are used by attributes and the test T key.
- Auras (weapons/auras/, <name>_aura.tscn + weapon_aura.gd):
  WeaponAuraClass: any Sprite2D child gets the weapon texture (glow via
  enchant.gdshader), any CPUParticles2D child emits from the blade
  pixels. fire, frost, poison, electric, water, arcane, blood,
  explosive, shadow, steel, prismatic, holy, celestial, void, crystal.
  New element = new aura + effect .tres.
  Particles are world space (local_coords off): they stay where they
  spawn and do NOT move with the player (developer, 2026-09-18; a
  wielder-space version was tried and rejected). EnchantClass extends it.
  Particles use soft_dot / sparkle.png, never bare square pixels, and
  stay sparse (developer: high rarity weapons had way too many).
  WeaponAuraClass puts its Sprite2D glow BEHIND the weapon sprite
  (show_behind_parent) and its particles in front (z_index 1), so the
  pixel art stays readable. A weapon shows at most MAX_AURAS (1) auras:
  the element effect's aura wins, else the first attribute's. Without
  the cap a legendary+ weapon stacked six glows in six colours.
  Summoned objects (swords, crystals, rocks) are pixel art sprites, not
  Polygon2D shapes (those looked like vector art and did not fit).
- WeaponClass.get_sprite() = first Visuals Sprite2D.
  WeaponClass.get_pixel_points(texture, bladeOnly) = opaque pixel
  positions for particle emission (bladeOnly keeps the top-right half,
  since sprites are drawn handle bottom-left). Scenes preloaded by
  weapon.gd must not reference WeaponClass (preload cycle), so pass
  data in instead.
- Totally different attacking: new attack type, or extend WeaponClass.

[Weapon items + upgrades]  godot/weapons/base/ (weapon_item.gd, weapon_upgrades.gd/.tres)
- WeaponItemClass (Resource) = ONE owned copy of a weapon: the
  thing inventories, loot drops and saves will hold. Exports
  weaponScene, rarity, level, combatLevel, rarityUpgraded, attributes
  (Array[AttributeRollClass]). Runes go on the item later.
- create_weapon() instantiates weaponScene with item, attributes and
  rarity set.
- level_up() (up to maxLevel 30, never blocked by the rarity
  upgrade), upgrade_rarity() (from rarityUpgradeLevel 15, only once,
  needs rarity.nextRarity, KEEPS the level and attributes and rolls
  the new slot), upgrade_combat_level(amount), randomize_attributes()

[Attributes]  godot/weapons/attributes/
- AttributeClass (base/attribute.gd) = one attribute definition, a
  .tres in normal/ or special/. Exports attributeName, description
  ("{value}", "{chance}" and other placeholders, % and ° written in
  the text), stat, scaling, trigger, chanceScaling, effectScene (VFX
  spawned by spawn_effect), auraScene (weapon aura added on equip,
  one per scene), attackTypes, special, inRandomPool, weight (roll
  chance weight; specials use 0.6, attributes that need something
  else on the weapon 0.7-0.8).
- inRandomPool = ON/OFF switch: off = never picked by random rolls
  (still usable as a fixed artifact attribute). Every special .tres
  writes it out explicitly. For now EVERY attribute is on (testing).
- EFFECTS = trigger + chance (developer: effects are a chance, never a
  guarantee). trigger (enum AttributeClass.Trigger): NONE, ATTACK,
  HIT, CRIT, KILL, PROC (5, synergies only). chanceScaling = chance per trigger (scales with
  quality/level like scaling; empty = always). The base class turns
  on_attack/on_hit/on_crit/on_kill into on_proc(weapon, roll, hurtbox,
  damage) when the trigger matches and weapon.roll_chance() succeeds.
  ATTACK procs get hurtbox null, damage 0. Kill/crit buffs (Frenzy,
  Bloodlust, Adrenaline, Precision, Wind Up) have no chance: they are
  conditional stat bonuses, not effects.
- attackTypes = AttackTypeClass list where it can roll. Empty = every
  attack type. ONE attribute works for many attack types: add the
  type to its list instead of making a copy (e.g. Slash Size is
  [slash]; a future smash just gets added and reads the same stat).
- stat (enum AttributeClass.Stat): NONE, DAMAGE, CRIT_CHANCE,
  CRIT_DAMAGE, ATTACK_SPEED, KNOCKBACK, ATTACK_SIZE, ATTACK_ARC,
  EXTRA_TARGETS, STATUS_DAMAGE, MOVE_SPEED (10), STATUS_DURATION (11),
  EFFECT_CHANCE (12), EFFECT_AREA (13), EFFECT_DAMAGE (14, proc
  damage: get_effect_damage_multiplier), PIERCE (15, projectile
  maxHits), EXTRA_PROJECTILES (16).

  weapon.get_stat(stat) where the stat matters (slash reads
  ATTACK_SIZE, ATTACK_ARC, EXTRA_TARGETS; player reads MOVE_SPEED;
  apply_status reads STATUS_DURATION; roll_chance reads EFFECT_CHANCE;
  area effects read EFFECT_AREA). Only ADD new stats/triggers at the
  end of the enum (.tres files store the number).
  get_stat asks every attribute get_stat_bonus(stat, quality, level)
  (default: value if stat matches), so one attribute can give several
  stats (TradeoffAttributeClass).
- AttributeScalingClass (base/, embedded in the .tres): minBase,
  maxBase (value at attribute level 0 for the worst/best roll),

- BALANCE RULE (developer): attributes must not be op, and weapons
  felt way too strong (twice). Level 0 values are small and grow about
  3-4x by attribute level 30. Targets at level 30 with a perfect roll:
  plain stats (Damage, Attack Speed, Slash Size, Move Speed) 10-12%,

  capped low (+1 at level 15-20, never more). Damage over time values
  are % of weapon damage PER TICK and must stay visible at level 0
  (a tick below 0.5 shows as 0: that looked like no damage).

[Slash]  godot/weapons/attacks/ (slash_attack.gd, slash.gd/.tscn/.gdshader, slash_style.gd)
- SlashAttackClass node in a weapon: radius (middle of the swept
  band, from wielder center), size (band thickness), curve (arc
  degrees), maxTargets, raritySizeGrowth, swingsWeapon, styleOverride
  (custom style, e.g. artifacts).
  A weapon may hold SEVERAL SlashAttack nodes (halberd: front thrust +
  back sweep). Only one of them may have swingsWeapon on, the others
  would fight it over the swing animation. Rotate the extra node in the
  scene to aim it (the back sweep is rotated 180 deg).
  Each attack: spawns ONE slash.tscn as child of the wielder, swings
  weapon Visuals over 70% of duration, alternates swing direction.
- Size = (1 + (style.sizeMultiplier - 1) x raritySizeGrowth) x
  (1 + Slash Size attribute). raritySizeGrowth 1 = normal, higher =
  grows more per rarity (spear uses 2.5).
  Curve = curve + style.curveBonus + Slash Arc (max 360).
  Targets = maxTargets + Cleave (hitbox maxHits, nearest first).
- Curve 360 = full spin: slash and weapon start and end at the aim
  direction, hitbox is a full circle.
- Style = styleOverride, else weapon.rarity.slashStyle.
- SlashStyleClass (Resource): duration, sizeMultiplier, curveBonus,
  trail, glow, core, tipGlow, streaks, chromaticAberration,
  orbAmount, hitSparkSize, hitSparkAmount,
  screenShake, hitStop.
- screenShake (2.0) and hitStop (0.04) are capped at epic: legendary+
  use the same. More shake felt like too much, more hit stop froze
  the game up to 20% of the time while attacking and felt laggy.
- Look = ONE filled crescent (like Terraria Cooler Weapon Effects),
  drawn by slash.gdshader on a MeshInstance2D arc mesh built in code.
  The developer disliked stacked lines/echo arcs: never go back to
  layering separate arcs. Higher rarity = longer trail, glow, white
  rim, streaks (noise texture), rim-only RGB fringe, wider curve.
- Shader uniforms set from slash.gd; "head" (0-1) is the blade
  position along the arc, "trail" the fading length behind it.
  ShaderMaterial is local_to_scene so every slash has its own.
- Colors: taken automatically from the weapon's Visuals Sprite2D
  (dark/main/light by luminance, cached per texture), or from
  SlashAttack colorTexture if set (spear uses iron_sword.png).
- Particles: none on the arc. Glowing orbs spawn only at the HIT
  location (Vfx.show_hit_spark). No dust anywhere: the developer
  removed it, it looked out of place.
- Own HitboxComponent: sector polygon from radius/size/curve, mask
  Enemy Hurtbox, active first 60% of duration. Max targets: slash
  maxTargets (3, spear 4) + Cleave (+1, +2 at level 20), nearest first.
  On hit: hit spark + register_hit per enemy; GameFeel hit stop +
  shake only once per slash (hitFeelPlayed), however many enemies.
  The arc hides and stops processing once it has faded.
- slash.gd types "attack" as AttackClass on purpose: typing it as
  SlashAttackClass creates a preload cycle (slash_attack.gd preloads
  slash.tscn) and breaks opening slash.tscn.
- Smooth VFX nodes use texture_filter Linear (project default is
  Nearest). Pixel art VFX stays Nearest.
- Shaders follow the same style (2 blank lines after the header,
  camelCase uniforms, //------------------------// separator).

[VFX]  godot/vfx/
- PERFORMANCE RULE (developer: must run on the worst PCs, but never
  change what the player sees): every effect goes through the Vfx
  autoload (core/vfx.tscn + vfx.gd), never instantiate effects
  yourself. See [Vfx budget] below.
- effects/hit_sparks.tscn: HitSparksClass draws EVERY hit spark in one
  node (flash + star spikes + spark streaks + glowing orbs, particle
  math copied from CPUParticles2D). Look = its exports (textures,
  curves, gradients, speeds). Call Vfx.show_hit_spark(position, color,
  strength, sparkAmount, orbAmount, angle).
- effects/damage_numbers.tscn: DamageNumbersClass draws every damage
  number in one node (pop, rise, fade, crit = bigger, critColor, "!",
  text via NumberFormatClass). Pixel identical to the old Label version
  (same layout math as Godot's Label). Call Vfx.show_damage_number().
  Numbers of the SAME colour landing within mergeRadius inside mergeTime
  add into one growing number; anything else stacks stackHeight upwards
  (up to maxStack) instead of covering the older number. Without this a
  weapon with many attributes wrote three numbers on the same pixels.
- QUALITY BAR (developer): every effect must be as juicy as the
  burn, frost and poison visuals: layered glow + flash + particles,
  never a single cheap shape.
- NO RINGS unless the effect really is an area pulse: only Nova,
  Repulse, Vortex and Time Warp keep one (the developer found rings
  everywhere too much).
- ONLY FROST CHANGES THE SPRITE (its freeze overlay). Other status
  visuals never recolor or overlay the target: body glows and dark
  smoke/tar go BEHIND the sprite (z_index -2 inside the visual).
- Framework (vfx/base/): VfxEffectClass = root of every one-shot
  effect scene (baseRadius: scaled by radius / baseRadius, lifetime,
  shake, tinted: nodes that take the spawn color). Effects are POOLED:
  play() restarts it, after lifetime it emits finished and Vfx hides
  it for reuse (not pooled = frees itself). Every part must be
  restartable: parts get restart() (elapsed = 0, rebuild randoms),
  CPUParticles2D restart themselves. A new part script needs restart().
  Parts to build effects in the editor: VfxFlashClass (Sprite2D scale
  + fade, loop), VfxSpikesClass (star spikes), VfxRingClass (only for
  the 4 above), VfxArcsClass (electric arcs), VfxOrbitClass (STAR or
  SHARD shapes orbiting), VfxReticleClass (corner brackets).
  Keep effect roots at z_index 2 (pooled effects live under the
  autoload, which draws before the level at equal z).
  vfx/shared/: additive material, soft dot/glow, flash, streak, pixel,
  bubble textures, sparkle.png (4 point star glint) and
  puff/shrink/twinkle curves. Reuse them.
- vfx/effects/ holds every effect scene (no folder per effect):
  splash, water_splash, explosion, nova, crit_burst, smite,
  thunderclap, time_warp, contagion, vortex, repulse, execute,
  heavy_impact, spark_burst, reset_flash, ice_spikes, mark_burst,
  shrapnel_burst, soul_release, cast_flash, heal_burst, hit_sparks,
  lightning, damage_numbers, volatile_pop, jackpot, aftershock,
  wild_magic, star_impact, sunlance (beam, baseRadius
  = length), catalyst, rend, crystal_shatter, doom_burst,
  singularity_collapse, soul_bind, frost_nova, inferno, divine_wrath,
  dread. smite = light column + ground glow + arcs + motes.
  Kept subtle: several at once must not blow out to white.
- Buff visuals (vfx/buffs/<name>_buff.tscn): BuffVisualClass on the
  wielder, tiers (particle emitters turned on by stack count), stop()
  fades.
- effects/lightning.tscn: LightningClass jagged bolt between points (global
  positions, node sits at the scene origin), midpoint displacement
  bolts drawn as soft feathered ribbons (static draw_bolt / draw_layers:
  wide glow, colored body, white core, tapered; VfxArcs and Soul Link
  use them too; the old polylines looked harsh), soft end glows,
  re-jagged every flickerTime, fades over duration. Vars: points, color. Used by Chain Lightning,
  Smite (bolt from above the target) and Shock (arc to a neighbour),
  always through Vfx.spawn_lightning(scene, points, color, width).

[Vfx budget]  godot/core/vfx.tscn + vfx.gd  (autoload "Vfx")
- Children: HitSparks, DamageNumbers (batched drawers), Pool (pooled
  one-shot effects), Warmup. All budget numbers are exports on the root.
- Idea (developer): full effects where the player looks, less where it
  cannot be seen: off screen (view rect + cullMargin) nothing spawns,
  and "the ones below" (stacked enemies, same effect on the same spot)
  only get one copy. Normal play looks exactly like before.
- spawn_effect(scene, position, radius, color, parent): skipped when off
  screen, when effectsPerCrowd copies of that scene started within
  max(crowdRadius, radius / 2) in effectCrowdTime, or when maxEffects /
  maxEffectsPerScene are alive. Skipped effects still shake the camera
  (shake read from the scene). parent = null -> pooled.
  AttributeClass.spawn_effect, frostbite and meteor impacts use it.
- can_spawn(key, position, perCrowd) = the same check for anything
  else (life orbs). show_hit_spark / show_damage_number / spawn_lightning
  use sparksPerCrowd / numbersPerCrowd / boltsPerCrowd.
- Status visuals: StatusComponent asks add_status_visual(effect); only
  on-screen visuals are created, max statusVisualsPerCrowd per effect
  name per statusCrowdRadius cell, max maxStatusVisuals total. Every
  updateInterval the rest is hidden (visible off + process disabled =
  free) and shown again when needed (created late = no Burst:
  StatusVisualClass.skipBurst). StatusEffectClass.on_visual_created()
  runs when a visual is made late (frost syncs its build up there).
  pulse_visual() skips hidden visuals.
- add_cullable(node): moving visuals (slash waves, spirit orbs, status
  zones) are hidden while off screen; gameplay keeps running.
- Warmup: the first frames instantiate every scene in warmupFolders
  (vfx/effects, vfx/buffs, status_effects) nearly invisible so shaders
  compile at load, not on the first hit; VfxEffect scenes stay in the
  pool.
- IMPORTANT: vfx.gd must NOT use status/hurtbox class types (it uses
  Resource + duck typing). An autoload with typed references to the
  status_effect / status_component / hurtbox scripts makes Godot leak
  those scripts at exit ("resources still in use").
- Portals hide themselves completely when closed or off screen.
- Verify performance with a benchmark scene in a scratch copy
  (40 stacked enemies, strong weapon, vsync off, frame times) in both
  renderers (Mobile and gl_compatibility = web).

[Status effects]  godot/status_effects/

- StatusEffectClass (base/): Resource with effectName, duration,

- StatusVisualClass (base/status_visual.gd): root of the new status

- Burn (fire/): BurnEffectClass damagePerTick, damageType (fire).

  removes it.
- Frost (frost/): FrostEffectClass build-up. Each hit = 1 stack
  (frost_visual.tscn: FrostVisualClass copies status.sprite into an
  Overlay with frost_overlay.gdshader that freezes the sprite from the

  stacksToProc (4) = frostbite:
  frostbiteDamage (20, ice = blue numbers) + frostbite_explosion.tscn

  then removed. Build-up clears after duration (4s) without hits.

- Poison (poison/): PoisonEffectClass damagePerStack, maxStacks (5),

- Shock (lightning/): ShockEffectClass damagePerTick, damageType

- Wet (water/): WetEffectClass slowAmount (0.15), amplifiedType
  (lightning) + amplifiedBonus (0.25, set_strength): wet targets take

- Slow (debuffs/): SlowEffectClass slowAmount (0-1, speed multiplier =

- Stun (debuffs/): stun.tres uses SlowEffectClass with slowAmount 1,

- Sunder (debuffs/): SunderEffectClass damageTakenBonus (target takes

- Crystal (debuffs/): CrystalEffectClass: stunned (speed 0) for 1s, then

- Doom (debuffs/): DoomEffectClass stores all damage taken (status

- Modifiers (modifiers/): enemy spawn modifiers. ONE script,

[Paths]  godot/paths/
- Level setup: a PathNetwork node (PathNetworkClass) with
  EnemyPath children (EnemyPathClass, extends Path2D). Draw the curve
  with the Path2D tools: first point = start, last point = end.
  Paths must be children of a PathNetwork.
- EnemyPath exports: active (off = no pulse, no enemies branch into or
  merge into it; setter emits active_changed), branchFrom (this path
  starts on that path at the closest point), mergeInto (this path's
  end joins that path at the closest point, enemies continue on it),
  cornerRadius. Start/end are snapped onto the connected path, so
  placing them roughly is enough.
- route = the Curve2D enemies and visuals use: the drawn curve with
  rounded corners (cornerRadius). get_length(), get_global_point(d),
  get_closest_distance(point). branches = paths branching off it.
- RULE (developer): path lines only show and connect where enemies of
  the upcoming wave will actually walk. A branch/merge line nobody
  walks on makes no sense.
- Pulse animation (between waves and at level start): purple glowing
  pulse travels from the spawn paths through active branches and
  merges, leaves an afterglow, then fades and repeats (network clock,
  all paths in sync). Only paths the pulse reaches are visible.
  set_spawn_paths(paths) (WaveManager passes the paths of the next
  wave's portals; empty = every active path that is not fed by a
  branch). A spawn path holds a Portal node (see [Waves]).
  play_preview() / stop_preview(). During a wave (stopped) the same
  paths stay visible, grayed out and transparent (waveOpacity).
  playOnStart export.
- Look + timing: path_pulse_style.tres (PathPulseStyleClass),
  the network's style export (default = that file).
- path_pulse.tscn: spawned per path at runtime. Line
  (MeshInstance2D, strip mesh built in code, path_pulse.gdshader
  additive), head halos drawn in _draw (headTexture), StartDot and
  EndDot (path_dot.tscn: glow, core, ring pop; shown when the pulse
  reaches them). Only spawn starts (pulse isSpawn) and final ends get
  a dot: no dots on connection points (branch starts, merge ends), the
  developer thought they looked off.
  Mesh inner width is limited around bends so it never folds (the
  developer saw spiky artifacts before that).
- Draw layer: path pulse is z_index -5 (absolute). Ground/tilesets
  must be below that (e.g. -10); characters stay at 0.

[Enemies]  godot/enemies/
- EnemyClass (enemy.gd + enemy.tscn, CharacterBody2D, layer

  healthComponent, movementComponent, pathFollowComponent,
  statusComponent. Visuals/
  Sprite2D like the player, walk animation, Hurtbox (Enemy Hurtbox) +
  StatusComponent. Health x COMBAT_SCALING.get_multiplier(combatLevel)
  x healthMultiplier; movementComponent.speedMultiplier =
  speedMultiplier; modifier (set = always that modifier, empty = the

  reached_end -> on_reached_end() (queue_free for now, no crystal yet).

- Spawn modifiers: EnemyModifiersClass (enemy_modifiers.gd/.tres,

- New enemy = inherited scene of enemy.tscn, set stats on the

[Waves]  godot/waves/
- Setup is all nodes: WaveManager > Wave nodes (amount of waves =
  amount of Wave children, in order) > SpawnGroup nodes (which enemy,
  how many, from which portal). Duplicate nodes to add waves/groups.
- WaveManager node (WaveManagerClass): exports pathNetwork,
  enemyParent (empty = current scene), combatLevel. start_next_wave(),
  get_wave() (running or next wave, null = all done),
  get_enemies_left(), autoStartTimeLeft (countdown, 0 = manual).
  Signals wave_started, wave_finished, all_waves_finished,
  enemy_spawned(enemy). A wave ends when everything spawned and every
  enemy is gone. Enemy combat level = combatLevel + wave bonus + group
  bonus; health/speed = wave x group multipliers.
  Enemies only count as removed when queue_freed (dying or reaching
  the end), so quitting the game never triggers spawns.
- Wave node (WaveClass): waveName (shown in the HUD, empty = none),
  autoStartTime (0 = wait for start_next_wave, above 0 = starts by
  itself that many seconds after it became next), activatePaths /
  deactivatePaths (e.g. a branch enemies may take from now on),
  Enemy Stats group: combatLevelBonus, healthMultiplier,
  speedMultiplier. get_spawn_groups(), get_portals(),
  get_spawn_paths(), get_enemy_count().
  When a wave is NEXT (level start / previous wave done):
  deactivatePaths turn off, activatePaths turn on, every path its
  portals sit on turns on (plus the paths they merge into, so enemies
  always reach an end), the network gets its spawn paths, the path
  preview plays and its portals show the warning rift.
- SpawnGroup node (SpawnGroupClass): enemyScene, portal, count,
  burst (enemies per spawn moment), interval, intervalRandomness
  (0-1, +- that fraction). Start group: startAfter (WAVE_START,
  PREVIOUS_SPAWNED = after the group above finished spawning,
  PREVIOUS_CLEARED = after every enemy of the group above died or
  reached the end), delay (seconds after that). Enemy Stats group:
  combatLevelBonus, healthMultiplier, speedMultiplier, modifier (a
  status .tres from status_effects/modifiers/, forced on every enemy).
  Signals finished_spawning, cleared.
- Portal (portal.tscn, PortalClass) = a spawn point. Put it INSIDE
  the EnemyPath it spawns on: on ready it moves to the path's first
  point. Enemies pop out of it (Visuals scale.y grows with a bright
  emergeColor flash, spawnSpread = random offset). States: CLOSED
  (hidden), WARNING (the next wave uses it: thin flickering rift),
  OPEN (while any of its groups spawn: swirling vortex; open() /
  release() count users, closes closeDelay after the last one).
  Exports color (everything in tinted + the shader rim/glow), voidColor,
  openTime, closeTime, closeDelay, warningSize, warningIntensity,
  spawnSpread, emergeTime, emergeColor.
  Body = Sprite2D with portal.gdshader (blend_premul_alpha: darkens
  the void AND adds glow in one pass; spiral arms, noise swirl,
  wobbling rim, halo; uniforms intensity + flash set by the script).
  Particle groups: OpenLoop (smoke, inward orbiting motes, rim sparks),
  WarningLoop (drift, crackle), OpenBurst / SpawnBurst / CloseBurst
  (one-shot, restarted by play_burst). Looks the same in the
  Compatibility (web) renderer.
  Baking all of this into a spritesheet was tried and REJECTED
  (developer, 2026-09-20): the baked frames looked worse than the live
  shader. Leave the portal as shader + particles.

[Towers]  godot/towers/
- Dungeon Defenders 2 rules. Enemies drop green MANA on death
  (EnemyClass.manaReward). Building costs mana AND the same amount of
  DEFENSE UNITS out of the map budget; the units come back when the
  tower is sold or destroyed.
- TowerStatsClass (.tres, one per tower type) is where ALL the balance
  lives: towerScene, manaCost, upgradeCost + upgradeCostPerTier,
  sellRefund, repairFactor, maxTier, health + healthPerTier, damage +
  damagePerTier, attackCooldown, attackRange, maxTargets, damageType.
  New tower = new scene + new .tres, add it to a character's list.
  Repair cost = manaCost x repairFactor (0.75) x missing health, like
  DD2. Sell gives back sellRefund of everything spent (build+upgrades).
- THREE TIERS (1-2-3) and an upgrade must CHANGE WHAT THE TOWER DOES,
  not only raise numbers (developer: tier 1 was too strong and max tier
  was boring). The generic numbers in TowerStats stay small; the tier
  behaviour is exported on the tower's own scene, so a new tower writes
  its own. Only the barricade is numbers-only for now.
  * Bolt Tower: boltsPerTier 1/2/3 (it fires that many bolts, spread
    over the nearest targets), piercePerTier 1/1/3, and from
    statusFromTier (3) every bolt applies its status (Shock).
    7 -> 10.5 -> 14 damage, so 7 -> 21 -> 42 per volley.
  * Flame Brazier: plain damage at tier 1, adds its status (Burn) from
    statusFromTier (2), and from eruptFromTier (3) every eruptEvery
    (4th) tick erupts for eruptDamage (x3) over eruptRadius (x1.6) and
    spawns eruptScene. Normal ticks only flash the ring, no effect
    scene, so a brazier does not spam VFX.
  * Barricade: health only, 420 / 672 / 924.
- Placing snaps to a gridSize (8) grid, the same grid the lanes are
  drawn on, so the ghost jumps cell to cell instead of sliding.
- Picking a tower is by HOVER, not by distance: TowerClass.get_hover_rect()
  (hoverSize + hoverOffset, so it covers the sprite and not the ground
  under it) and TowerBuilder.get_hovered(). Upgrade / repair / sell still
  need the player within reachDistance (can_reach), the tooltip says
  "move closer" when they are not.

[Minimap]  godot/ui/minimap.gd + minimap.tscn
- MinimapClass, a Control drawn with _draw() at updateInterval (0.1s).
  Exports pathNetwork, waveManager, towerBuilder, player, mapSize and
  groundTexture; everything is drawn by scaling world positions into the
  control's size, floored, so it stays pixel aligned.
- It TAKES THE LEVEL'S OWN COLOURS, it does not invent a palette: the
  real ground texture (texture_repeat on, drawn with
  draw_texture_rect_region over mapSize so it tiles like the level), the
  path colours from PathNetwork.style (color + coreColor), each portal's
  own color, each tower's get_color() and each enemy's sprite modulate.
- Lanes are drawn in three passes over every path (3px dark outline,
  2px path colour, 1px core) so they read on top of the noisy ground.
  Inactive lanes and their portals are darkened() by lockedFade, NOT
  made transparent: stacking three translucent passes added back up to
  almost full brightness and locked lanes looked open.
- TowerClass (tower.gd) = StaticBody2D root. HealthComponent for
  Defense Health, a health bar that hides at full, a build pop, tier
  (1-5: upgrade() raises health and damage and refills), destroy() on
  0 health. attack() is the one thing subclasses override; it returns
  true when it fired, and the cooldown only runs then. get_targets() /
  get_closest_target() search the Enemy Hurtbox layer inside range.
- bolt_tower.gd: fires a homing spirit orb at the nearest enemy.
  aura_tower.gd: damages everything in its ring and applies a status
  (burn), with a Ring sprite scaled to attackRange.
  barricade.tscn needs no script: no attack, lots of health, blocks.
- TowerBuilderClass (tower_builder.gd) is a node INSIDE the player
  scene and holds that character's three TowerStats: every character
  gets their own three towers this way. It also holds mana and the
  defense unit budget (ponytail: the budget belongs to the map later).
  select() / select_next() show a ghost that follows the mouse and
  turns red where it cannot build, build_at(spot) pays and places,
  upgrade() / repair() / sell() take a tower, get_nearest(spot) finds
  the one in reach. It hooks WaveManager.enemy_spawned to pay out mana.
- Enemies attack whatever they walk into: EnemyClass.attack_blocker()
  checks its slide collisions for a TowerClass and hits it every
  attackCooldown for attackDamage x the combat level multiplier.
